# 01. State-Space Search & Lexicographic Fitness Vectors

[← Back to Master Index](../README.md)

This module documents the multi-objective state-space search framework powering the **Custom State-Space Engine**.

---

## 1. Discrete State Tuple Formulation

The layout solver models candidate layout configurations as a discrete state tuple $\sigma$:

$$\sigma = \left\langle \Pi_{\text{sides}}, \Omega_{\text{ports}}, \mathcal{D}_{\text{demands}}, \mathcal{L}_{\text{orders}}, \Delta_{\text{shifts}} \right\rangle$$

```
                           State Tuple (σ)
        ┌────────────────────────────────────────────────────────┐
        │  Π_sides: Node Edge Connection Port Sides              │
        │  Ω_ports: Ordering Index of Edge Ports per Side        │
        │  D_demands: Active Node Gap Spacing Overrides (G_req)  │
        │  L_orders: Node Ordering Sequence per Rank Layer       │
        │  Δ_shifts: Fine X/Y Coordinate Alignments              │
        └────────────────────────────────────────────────────────┘
```

---

## 2. Lexicographic Fitness Vector $\mathbf{C}(\sigma)$

Evaluating candidate state $\sigma$ yields a multi-criteria cost vector evaluated in strict lexicographic priority order:

$$\mathbf{C}(\sigma) = \left\langle C_{\text{hard}}(\sigma), C_{\text{cross}}(\sigma), C_{\text{bends}}(\sigma), C_{\text{length}}(\sigma), C_{\text{badges}}(\sigma) \right\rangle$$

```
                           Lexicographic Hierarchy
            ┌──────────────────────────────────────────────────┐
            │ Priority 1: C_hard (Hard Conflicts / Overlaps)  │
            └────────────────────────┬─────────────────────────┘
                                     │ (Must be 0)
                                     ▼
            ┌──────────────────────────────────────────────────┐
            │ Priority 2: C_cross (Edge Crossings)             │
            └────────────────────────┬─────────────────────────┘
                                     │ (Minimize)
                                     ▼
            ┌──────────────────────────────────────────────────┐
            │ Priority 3: C_bends (Route 90° Bends)            │
            └────────────────────────┬─────────────────────────┘
                                     │ (Minimize)
                                     ▼
            ┌──────────────────────────────────────────────────┐
            │ Priority 4: C_length (Total Manhattan Distance)  │
            └────────────────────────┬─────────────────────────┘
                                     │ (Minimize)
                                     ▼
            ┌──────────────────────────────────────────────────┐
            │ Priority 5: C_badges (Badge Separation Penalty) │
            └──────────────────────────────────────────────────┘
```

### Strict Lexicographic Comparison Operator

State $\sigma_A$ is strictly superior to state $\sigma_B$ ($\sigma_A \prec \sigma_B$) if and only if at the first index $k \in \{1, 2, 3, 4, 5\}$ where $C_k(\sigma_A) \neq C_k(\sigma_B)$, we have $C_k(\sigma_A) < C_k(\sigma_B)$.

---

## 3. Neighborhood Perturbation Operators

From candidate state $\sigma$, neighboring search states $\mathcal{N}(\sigma)$ are generated by applying discrete perturbation operators:
1. **Port Order Permutation**: Swap pin positions of adjacent edges on the same node side.
2. **Side Flip**: Move edge connection port from `bottom` to `left`/`right`.
3. **Layer Order Swap**: Swap horizontal positions of adjacent nodes on rank layer $L_r$.
4. **Spacing Demand Expansion**: Inject required node gap $G_{\text{req}}$ to resolve badge clearance.
